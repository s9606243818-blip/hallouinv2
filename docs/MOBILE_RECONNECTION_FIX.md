# 📱 Исправление проблемы с блокировкой экрана на мобильных

## 🐛 Проблема

При блокировке экрана телефона или сворачивании приложения:
- WebSocket соединение разрывается
- Игрок исчезает из списка онлайн
- Другие игроки видят, что он вышел из игры
- При разблокировке нужно заново входить

## ✅ Решение

### 1. **Page Visibility API**
Отслеживаем когда страница скрывается/показывается:
```javascript
// Определяем события в зависимости от браузера
document.addEventListener('visibilitychange', () => {
  if (!document.hidden) {
    // Страница снова видима - проверяем соединение
    socket.reconnect();
  }
});
```

### 2. **Улучшенные настройки Socket.IO**
```javascript
io({
  reconnection: true,              // Автопереподключение
  reconnectionAttempts: Infinity,  // Бесконечные попытки
  reconnectionDelay: 1000,         // 1 секунда между попытками
  reconnectionDelayMax: 5000,      // Максимум 5 секунд
  timeout: 20000,                  // Таймаут 20 секунд
  transports: ['websocket', 'polling'], // WebSocket + fallback
});
```

### 3. **Автоматическое повторное подключение**
```javascript
socket.on('connect', () => {
  // Если это переподключение - заново входим в игру
  if (this.userNickname) {
    this.emit('join', { 
      nickname: this.userNickname,
      avatar: this.userAvatar,
      isRejoin: true 
    });
  }
});
```

## 📱 Как это работает на практике

### Сценарий 1: Блокировка экрана телефона

```
1. Игрок заблокировал экран
   ↓
2. Страница скрыта (visibilitychange)
   ↓
3. Socket.IO поддерживает соединение
   ↓
4. Игрок разблокировал экран
   ↓
5. Страница видима (visibilitychange)
   ↓
6. Проверка соединения
   ↓
7. Если разорвано - автопереподключение
   ↓
8. Повторный вход в игру (rejoin)
   ↓
9. Игрок снова онлайн!
```

### Сценарий 2: Переключение между приложениями

```
1. Игрок свернул браузер
   ↓
2. Window blur event
   ↓
3. Socket.IO поддерживает соединение в фоне
   ↓
4. Игрок вернулся
   ↓
5. Window focus event
   ↓
6. Отправка ping для проверки
   ↓
7. Соединение живо - игра продолжается
```

### Сценарий 3: Потеря интернета

```
1. Интернет пропал
   ↓
2. Socket disconnect
   ↓
3. Автоматические попытки переподключения (каждые 1-5 сек)
   ↓
4. Показывается индикатор "Переподключение..."
   ↓
5. Интернет появился
   ↓
6. Socket reconnect
   ↓
7. Повторный вход в игру
   ↓
8. Индикатор исчезает
```

## 🔍 События Socket.IO

### Новые обработчики:

```javascript
// Успешное переподключение
socket.on('reconnect', (attemptNumber) => {
  console.log(`Переподключение после ${attemptNumber} попыток`);
});

// Попытка переподключения
socket.on('reconnect_attempt', (attemptNumber) => {
  console.log(`Попытка ${attemptNumber}...`);
});

// Ошибка переподключения
socket.on('reconnect_error', (error) => {
  console.error('Ошибка:', error);
});

// Не удалось переподключиться
socket.on('reconnect_failed', () => {
  // Показываем ошибку пользователю
});
```

## 🧪 Как протестировать

### Тест 1: Блокировка экрана
1. Откройте игру на телефоне
2. Заблокируйте экран (кнопка питания)
3. Подождите 10 секунд
4. Разблокируйте экран
5. ✅ Вы должны остаться в игре

### Тест 2: Переключение приложений
1. Откройте игру на телефоне

3. Подождите 30 секунд

5. ✅ Вы должны остаться в игре

### Тест 3: Потеря интернета

2. Сверните Telegram
3. Подождите
4. Откройте Telegram снова
5. ✅ Игра продолжается

## 🚨 Важные замечания

### ❗ iOS Safari
- На iOS Safari есть ограничения для фоновых процессов
- После 30 секунд в фоне соединение может разорваться
- Наше решение автоматически переподключает

### ❗ Telegram WebView
- Telegram может убивать фоновые процессы агрессивнее
- Наше решение учитывает это через Page Visibility API

### ❗ Экономия батареи
- Некоторые телефоны агрессивно убивают фоновые процессы
- Socket.IO будет пытаться переподключиться при возврате
